Here are the details on the services and input parameters we are passing from the front-end on the Corporate Officer Exclusion Reasonableness Worksheet page:

1. Initial Page Load — IAccountSummaryService.GetCOEReasonablenessAsync(COEReasonablenessRequest) When the worksheet loads, we pass a COEReasonablenessRequest with:

EmployerSK: Selected employer's EmployerSK (int)
SecureUserSK: Logged-in user's SecureUserSK (int)
year: DateTime.Now.Year (2026) (Note: The payroll fields PayrollSubjectToFUTAWithoutCOE, PayrollSubjectToWITaxRateWithCOE, and PayrollSubjectToWITaxRateWithoutCOE are not set on initial load and default to 0 / null).

2. On "Recalculate" Click — IAccountSummaryService.GetCOEReasonablenessAsync(COEReasonablenessRequest) When the user clicks Recalculate, we call GetCOEReasonablenessAsync with:

EmployerSK: Selected employer's EmployerSK (int)
SecureUserSK: Logged-in user's SecureUserSK (int)
year: DateTime.Now.Year (2026)
PayrollSubjectToFUTAWithoutCOE: User-entered FUTA Payroll (decimal)
PayrollSubjectToWITaxRateWithoutCOE: User-entered WI Taxable Payroll Without COE (decimal)
PayrollSubjectToWITaxRateWithCOE: User-entered WI Taxable Payroll With COE (decimal)

3. On "Submit Election" Click — IAccountMaintenanceService.SaveNewCOEElectionAsync(CorporateOfficerExclusionRequest) (Note: The missing wage reports rule violation error is returned from this call in res.RuleViolations) When the user clicks Submit Election, we pass a CorporateOfficerExclusionRequest with:

EmployerSK: Selected employer's EmployerSK (int)
SecureUserSK: Logged-in user's SecureUserSK (int)
Year: DateTime.Now.Year (2026)
NetSavings: Calculated NetSavings from the worksheet response (decimal)
IsCalculateClicked: true if Recalculate was clicked, otherwise false (bool)
IsNoSavingsShown: false (bool, default)
