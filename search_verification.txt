The front-end fix has been implemented based on the resolution confirmed in the comments above.

Root Cause: Line 5 (Your 2026 WI UI Tax Rate) was mapping two different fields from COEReasonablenessProxy to the two columns:

Without Exclusion → WIUITaxRate (raw decimal scale, e.g. 0.0040)
With Exclusion → WIUITaxRatePercentage (percentage scale, e.g. 0.4000)

Since both were formatted using .ToString("P"), the 100× scale difference between the two fields caused the incorrect display (e.g. 0.40% vs 40.00%).

Fix Applied: Following the legacy portal behavior (WIUITaxRate.Value * 100), both columns on Line 5 are now mapped to the single correct field — COEReasonablenessProxy.WIUITaxRatePercentage — in both the GetData and Recalculate service methods, and in the Razor view.

Files Changed:

CorporateOfficerExclusion.razor — Both "Without Exclusion" and "With Exclusion" columns on Line 5 now render WIUITaxRatePercentage
CorporateOfficerExclusionService.cs — GetData() and Recalculate() both now map WIUITaxRate and WIUITaxRatePercentage from COEReasonablenessProxy.WIUITaxRatePercentage

Line 5 will now display the same correct tax rate value in both columns, matching the expected legacy portal behavior. This fix is ready for UAT validation.
